### 阶段一：工程化基础（1~2天）

**目标**：完成 Monorepo 改造，搭建前后端联调骨架。

```
├── packages/
│   └── shared-types/    # 新建 —— 前后端共享类型
└── package.json         # 改为 pnpm workspaces
```

- [ ] 将现有 `src/` 迁移到 `apps/web/`
- [ ] 初始化 `apps/server/`（Fastify + TypeScript）
- [ ] 创建 `packages/shared-types/`，将 `src/types/index.ts` 迁移至此，补充后端所需类型
- [ ] 配置 `pnpm workspaces`，统一 `tsconfig`

#### 1.2 后端骨架

文件：`apps/server/src/index.ts`

- [ ] Fastify 服务启动（端口 3001）
- [ ] WebSocket 插件（`@fastify/websocket`）
- [ ] 基础路由：`GET /health`、`GET /sessions`、`POST /sessions`
- [ ] WebSocket 事件协议定义（参见下方协议表）

**WebSocket 事件协议**：

| 事件 | 方向 | 说明 |
|------|------|------|
| `session:created` | S→C | 新会话创建完成 |
| `session:status` | S→C | 状态变更推送 |
| `terminal:data` | S→C | 终端输出流 |
| `terminal:input` | C→S | 用户输入 |
| `diff:update` | S→C | 文件变更推送 |
| `approval:required` | S→C | 触发审批弹窗 |
| `approval:decision` | C→S | 用户审批结果 |
| `broadcast:send` | C→S | 广播消息给 Agent |

#### 1.3 前端接入 WebSocket

- [ ] 创建 `apps/web/src/hooks/useWebSocket.ts`（连接管理、自动重连）
- [ ] Session Store 从 Mock 数据改为接收 WebSocket 事件驱动更新
- [ ] 连接状态指示器（TopNav 右侧）

### 阶段二：核心后端模块（3~5天）

**目标**：实现三大核心模块，使会话生命周期真正跑通。

#### 2.1 WorktreeManager

文件：`apps/server/src/worktree-manager.ts`

- [ ] `createWorktree(sessionId, taskName, baseBranch)` — 创建 Git Worktree + 新分支
- [ ] `removeWorktree(sessionId)` — 清理 Worktree
- [ ] `getDiff(sessionId)` — 获取与 baseBranch 的 diff（stat + full）
- [ ] `watchDiff(sessionId, cb)` — chokidar 监听文件变更，实时推送 diff
- [ ] `mergeToBase(sessionId, strategy)` — squash/merge/rebase 合并策略
- [ ] 依赖隔离：`node_modules` 软链复用
- [ ] 分支命名规范：`agent/<taskName>-<sessionId前8位>`
- [ ] Worktree 根目录：`<repo>/.agent-worktrees/<sessionId>/`

#### 2.2 TerminalMultiplexer

文件：`apps/server/src/terminal-mux.ts`

- [ ] `createTerminal(sessionId, cwd)` — node-pty 创建 PTY 进程
- [ ] `sendToTerminal(sessionId, data)` — 向终端写入
- [ ] `broadcastToAll(data, targets?)` — 广播给多个终端
- [ ] 输出捕获 + 环形 Buffer（保留最近 5000 行）
- [ ] Checkpoint 检测：`/\[CHECKPOINT\] (.+)/`
- [ ] 审批请求检测：`/\[APPROVAL_REQUIRED\] (.+)/`
- [ ] 事件发射：`terminal:data`、`approval:required`、`checkpoint:reached`

#### 2.3 SessionManager

文件：`apps/server/src/session-manager.ts`

- [ ] `createSession(params)` — 协调 WorktreeManager + TerminalMultiplexer
- [ ] `updateStatus(sessionId, status)` — 状态机转换（含校验合法转换路径）
- [ ] `getSession(sessionId)` / `listSessions()` — 查询接口
- [ ] SQLite 持久化（better-sqlite3），会话在重启后可恢复
- [ ] 会话状态机：

```
initializing → running → waiting → approved → running → completed → merged
                       ↘ rejected → paused → running（可恢复）
                                           ↘ failed
```

**依赖安装**（`apps/server`）：

```bash
pnpm add fastify @fastify/websocket node-pty simple-git chokidar better-sqlite3 execa fs-extra
pnpm add -D @types/better-sqlite3 @types/node
```

## 技术风险与注意事项

- **node-pty 在 Windows 上**：需要 Visual C++ Build Tools，开发建议在 WSL2 / macOS 下进行；或提供降级方案（`child_process.spawn` 模拟）。
- **Git Worktree 权限**：确保运行服务的用户对项目目录有读写权限；`.agent-worktrees/` 应加入 `.gitignore`。
- **xterm.js 与 React 18 Concurrent Mode**：xterm 直接操作 DOM，需在 `useEffect` 中初始化，避免 Strict Mode 双重挂载导致的内存泄露（使用 `useRef` 保护）。
- **Monaco Editor 包体积**：约 2MB，建议使用动态 `import()` 懒加载，仅在 Diff 弹窗打开时加载。
- **审批不可绕过**：`approval-workflow.ts` 中禁止 Agent 适配器自动回复 `y\n`，必须经过 `handleApproval` 接口。
