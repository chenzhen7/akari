# 状态变化机制

## 状态定义

| 英文值 | 中文含义 |
|--------|----------|
| `initializing` | 初始化中 |
| `running` | 运行中 |
| `waiting` | 待审批 |
| `approved` | 已批准 |
| `paused` | 已暂停 |
| `review` | 审查中 |
| `completed` | 已完成 |
| `failed` | 失败 |
| `merged` | 已合并 |
| `archived` | 已归档 |

---

## 状态转移图

```
初始化中 ──→ 运行中 ──→ 待审批 ──→ 运行中
    │            │         └──→ 已暂停
    └──→ 失败    ├──→ 已暂停 ──→ 运行中
                 ├──→ 已完成 ──→ 已合并 ──→ 已归档
                 ├──→ 失败   ──→ 已归档
                 └──→ 已归档
```

合法转移表：

| 当前状态 | 可转移到 |
|----------|----------|
| 初始化中 | 运行中、失败 |
| 运行中   | 待审批、已暂停、已完成、失败、已归档 |
| 待审批   | 运行中、已暂停、已归档 |
| 已批准   | 运行中、已归档 |
| 已暂停   | 运行中、失败、已归档 |
| 审查中   | 已完成、运行中、已归档 |
| 已完成   | 已合并、已归档、运行中 |
| 失败     | 已归档、运行中 |
| 已合并   | 已归档 |
| 已归档   | —（终止态） |

## 触发路径

### 1. 用户操作 → REST API → WebSocket 广播

```
用户操作（看板拖拽 / 审批按钮 / 归档）
  → fetch PATCH /sessions/:id/status
  → sessionManager.updateStatus()
      → SQLite 写入新状态 + kanban_column
      → broadcast({ event: 'session:status' })
  → 所有 WebSocket 客户端接收
  → handleServerMessage() → Zustand set → React 重渲染
```

### 2. Agent 终端输出 → 自动状态变化（核心路径）

Agent 进程运行时，`terminal-mux.ts` 持续解析 stdout，识别以下魔法字符串并自动驱动状态机：

| 终端输出 | 触发事件 | 状态变化 |
|----------|----------|----------|
| `[CHECKPOINT] <描述>` | `checkpoint:reached` | 进度 +10，状态不变 |
| `[APPROVAL_REQUIRED] type=...` | `approval:required` | 运行中 → 待审批 |
| `[SPAWN_AGENT] task=... agentType=...` | `spawn_agent` | 创建子会话（初始化中） |
| `[TASK_DONE] summary=...` | `task_done` | → 已完成 |
| 进程正常退出（exit code 0） | `terminal:exit` | 运行中 → 已完成 |
| 进程异常退出（exit code ≠ 0） | `terminal:exit` | 运行中 → 失败 |

完整链路：
```
node-pty 捕获 Agent stdout
  → terminal-mux.ts 正则解析输出
  → emit 内部事件（checkpoint:reached / approval:required / ...）
  → session-manager.wireEvents() 响应
  → updateStatus() → SQLite 更新
  → broadcast(session:status) → WebSocket → 前端 Zustand → UI
```

### 3. 会话创建时的自动流转

```
POST /sessions
  → createSession()
      → 写入 SQLite，状态：初始化中
      → broadcast(session:created) → 前端新增卡片
  → initSession() 异步执行
      → createWorktree()（创建 Git Worktree 与分支）
      → createTerminal()（node-pty 启动 Shell）
      → agent adapter 准备并延迟发送启动命令
      → updateStatus('running')  ← 自动变为「运行中」
      → 若任何步骤抛出异常 → updateStatus('failed')
```

### 4. 用户审批

```
用户点击「批准」/ 「拒绝」
  → fetch POST /sessions/:id/approval { decision: 'approved'|'rejected' }
  → sessionManager.handleApproval()
      → 审批通过：updateStatus('running') + 向终端发送 'y\n'
      → 审批拒绝：updateStatus('paused')  + 向终端发送 'n\n'
  → broadcast(session:status) → 前端更新
```

### 5. Pipeline 流水线触发（协作模式）

```
上游会话状态变为「已完成」
  → collaborationManager.onSessionCompleted()
  → 检查 pipelineEdges：trigger='on-complete' 的边
  → 自动创建下游子会话（状态：初始化中 → 运行中）
  → broadcast(collaboration:agent-spawned) → 前端新增卡片并弹 toast
```

### 6. WebSocket 连接时全量同步

```
新客户端连接 /ws
  → 立即推送 sessions:list（所有会话快照）
  → 推送所有 active 会话的当前 diff
  → 前端 handleServerMessage('sessions:list') → 覆盖 Zustand sessions
```

## 看板列与状态的映射

| 看板列 | 对应状态 |
|--------|----------|
| 待办（backlog） | 初始化中 |
| 进行中（in-progress） | 运行中、已暂停 |
| 待审批（waiting-review） | 待审批、审查中 |
| 已批准（approved） | 已批准 |
| 完成（done） | 已完成、失败、已合并、已归档 |

用户拖动看板卡片时，前端同时调用 `PATCH /sessions/:id/status` 将状态同步到后端。

## 触发源汇总

| 触发源 | 内部事件 | 状态变化 |
|--------|----------|----------|
| Agent 进程正常退出（exit 0） | `terminal:exit` | 运行中 → 已完成 |
| Agent 进程异常退出（exit ≠ 0） | `terminal:exit` | 运行中 → 失败 |
| Agent 输出 `[APPROVAL_REQUIRED]` | `approval:required` | 运行中 → 待审批 |
| Agent 输出 `[TASK_DONE]` | `task_done` | 当前状态 → 已完成 |
| Agent 输出 `[SPAWN_AGENT]` | `spawn_agent` | 新建子会话（初始化中 → 运行中） |
| 用户审批通过 | REST `POST /approval` | 待审批 → 运行中 |
| 用户审批拒绝 | REST `POST /approval` | 待审批 → 已暂停 |
| 用户拖看板 | REST `PATCH /status` | 按看板列映射 |
| 用户归档 | REST `POST /archive` | 当前状态 → 已归档 |
| Pipeline 上游完成 | `collaboration:agent-spawned` | 自动创建下游子会话 |
| 会话初始化完成 | `initSession()` 内部 | 初始化中 → 运行中 |
| 会话初始化失败 | `initSession()` catch | 初始化中 → 失败 |
