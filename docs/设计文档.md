## 一、产品定位与核心理念

```
核心理念：「指挥中心」模式
- 你是指挥官，Agent 是并行执行的士兵
- 无限画布 = 战场全局视图
- 看板 = 任务状态流转
- Tab = 快速聚焦单个战场
- Worktree = 物理隔离的并行战线
```

## 三、关键交互流程

### 3.1 创建会话

```
用户点击「新建会话」
  → 弹窗打开（填写任务名 / Agent类型 / 基础分支）
  → 提交
    → 弹窗内切换为进度视图
        「正在创建 Worktree...」
        「正在启动 Agent...」
    → 成功：弹窗自动关闭，自动跳转到新会话 Tab（状态: running）
    → 失败：弹窗内显示错误信息 + 「重试」按钮
            后台自动回滚已创建的 Worktree，用户可修改参数后重试
```

---

### 3.2 审批流程（基于 Claude Code HTTP Hook）

#### 触发

```
Claude Code 遇到需要权限的工具调用
  → 触发 PermissionRequest Hook
  → HTTP POST /sessions/:id/hooks { hook_event_name: "PermissionRequest", tool_name, tool_input }
  → HookDispatcher 记录审批日志
  → 当前实现：不挂起 Claude Code 原生权限流程，仍由 Claude Code 自己的确认机制处理
```

> **历史说明**：早期版本依赖 Agent 终端输出 `[APPROVAL_REQUIRED]` 魔法字符串触发审批，该机制已在 Phase 8 中完全废弃。

#### 审批弹窗内容（按类型区分）

| 类型 | 展示内容 |
|------|---------|
| `destructive-op` | 危险命令高亮展示 + 警告说明（不显示 Diff） |
| `merge-ready` | 完整 Monaco Diff Viewer + 合并策略选择（squash / merge / rebase） |

> **当前限制**：由于 `PermissionRequest` 尚未实现同步阻塞，统一审批中心和批量审批功能暂未生效。

---

### 3.3 广播消息

```
CommandCenter → 广播面板
  → 展示所有活跃会话列表（多选框）
  → 用户手动勾选目标会话
  → 填写广播消息内容
  → 发送 → 消息注入所有勾选会话的 Agent 终端
```

---

### 3.4 Review & Merge 流程

```
Agent 完成任务 → 状态变为 completed
  → 画布节点 / 看板卡片颜色变更（不自动弹出任何打断）
  → 用户主动进入会话详情页
  → 点击「Review & Merge」按钮
  → 打开合并面板：
      - 完整 Monaco Diff Viewer（与 baseBranch 对比）
      - 合并策略选择：squash / merge / rebase
      - 确认合并 → 后端执行 mergeToBase → 状态变为 merged
      - 取消 → 保持 completed 状态，可稍后再合并
```

---

### 3.5 Agent 消息与进度汇报

Claude Code 每轮回复结束时触发 `Stop` Hook，Akari 将 `last_assistant_message` 存入会话并广播 `session:lastMessage`，前端在会话卡片 / 节点消息区展示最新 AI 回复摘要。

> **历史说明**：早期版本通过终端输出 `[CHECKPOINT] <描述>` 魔法字符串汇报进度，该机制已在 Phase 8 中完全废弃。

---

### 3.6 画布节点交互

```
单击节点
  → 右侧滑出预览面板，展示：
      - 当前状态 + 最新 AI 消息摘要
      - 终端输出尾部（最近 10 行）
      - Diff 摘要（文件数 + 增删行数）
      - 快捷操作按钮（进入 Tab / 广播消息）
  → 预览面板不离开画布视图

双击节点
  → 跳转到该会话的详情 Tab
```

> **当前限制**：画布功能默认关闭（`CANVAS_ENABLED = false`），当前主入口为看板 + Tab 视图。

---

### 3.7 会话终止与清理

```
任何状态的会话均支持两步清理：

第一步：归档
  → 终止 Agent 进程（发 SIGTERM / kill PTY）
  → 保留 Git Worktree 和分支
  → 状态标记为 archived（可随时查看终端历史 / Diff）

第二步：彻底删除（在已归档会话上操作）
  → 弹出二次确认：「将删除 Worktree 目录和 agent/* 分支，不可恢复」
  → 确认 → 清理 Worktree 目录 + 删除本地分支 + 从 DB 移除记录
```

---

### 3.8 WebSocket 断线处理

```
连接断开
  → TopNav 连接状态指示灯变红
  → 鼠标悬浮指示灯显示：断开时长 + 已重试次数
  → 后台指数退避自动重连（不打断当前视图）

重连成功
  → 指示灯变绿
  → 拉取断线期间的终端 buffer 并回放到终端视图
  → 同步最新会话状态（防止断线期间状态变更丢失）

重连失败超过阈值（默认 10 次）
  → 指示灯变红并显示「×」标记
  → 顶部横幅提示「连接失败，请检查后端服务」+ 手动重连按钮
```

## 四、状态机

```
initializing ──→ idle ───────────────→ running
    │              │                      │
    │              ├──→ paused ──────────┤
    │              │         └──────── waiting
    │              │                      │
    │              └──→ failed            ├──→ completed ──→ merged
    │                                     │
    └──→ failed                           └──→ archived
```

主要状态说明：

| 状态 | 含义 |
|------|------|
| `initializing` | 创建会话、初始化 Worktree / PTY |
| `idle` | Claude Code 已启动，等待用户输入或任务恢复 |
| `running` | Agent 正在执行 |
| `waiting` | 等待用户审批（当前仅作展示，不阻塞 Agent） |
| `paused` | 会话暂停 |
| `completed` | 任务完成，等待 Review & Merge |
| `failed` | 执行失败 |
| `merged` | 已合并到基础分支 |
| `archived` | 已归档 |

详细状态流转见 [docs/状态变化机制.md](docs/状态变化机制.md)。

## 五、核心数据模型

详见 `packages/shared-types/src/index.ts`，关键类型：

- `AgentSession`：会话全量字段，包含 `tabs`、`activeTabId`、`workspaceId`、`lastAiMessage` 等
- `SessionStatus`：`'initializing' | 'running' | 'waiting' | 'paused' | 'review' | 'approved' | 'completed' | 'failed' | 'merged' | 'archived' | 'idle'`
- `AgentType`：`'claude' | 'aider' | 'shell' | 'claude-orchestrator'`
- `ServerMessage` / `ClientMessage`：WebSocket 协议消息联合类型
- `HookEvent` / `HookResponse`：HTTP Hook 事件类型
- `Workspace`：工作区模型
- `CanvasEdge`：画布连线模型

## 六、Worktree 与分支规范

- Worktree 基础目录：`<worktreeBaseDir>/<repoSlug>/<sessionId>/`（默认 `<repo>/.agent-worktrees/<repoSlug>/<sessionId>/`）
- 分支命名：`agent/<sessionId前8位>`
- 依赖隔离：通过符号链接复用 `node_modules`
- 清理：归档后可选择彻底删除，删除时移除 Worktree 目录与本地分支

## 七、HTTP Hook 机制

Agent 通过 Claude Code 的 `settings.local.json` Hook 配置向 Akari 后端发送生命周期事件，替代了早期的终端魔法字符串机制。已注册的 Hook 事件：

| 事件 | 触发时机 | Akari 行为 |
|------|----------|-----------|
| `SessionStart` | Claude Code 会话启动 | `initializing` → `idle` |
| `UserPromptSubmit` | 用户提交提示 | `paused` / `waiting` / `idle` → `running` |
| `PermissionRequest` | Claude Code 请求权限 | 记录日志（当前不阻塞） |
| `Stop` | 每轮回复结束 | `running` / `waiting` → `idle`，广播 `session:lastMessage` |
| `StopFailure` | API 报错 / token 超限 | `running` / `paused` / `waiting` → `failed` |

详情见 [docs/开发计划/phase-8-基于Hooks的Agent状态流程机制改造计划.md](docs/开发计划/phase-8-基于Hooks的Agent状态流程机制改造计划.md)。
