## 一、产品定位与核心理念

```
核心理念：「指挥中心」模式
- 你是指挥官，Agent 是并行执行的士兵
- 无限画布 = 战场全局视图
- 看板 = 任务状态流转
- Tab = 快速聚焦单个战场
- Worktree = 物理隔离的并行战线
```

## 三、关键交互流程

### 3.1 创建会话

```
用户点击「新建会话」
  → 弹窗打开（填写任务名 / Agent类型 / 基础分支）
  → 提交
    → 弹窗内切换为进度视图
        「正在创建 Worktree...」
        「正在启动 Agent...」
    → 成功：弹窗自动关闭，自动跳转到新会话 Tab（状态: running）
    → 失败：弹窗内显示错误信息 + 「重试」按钮
            后台自动回滚已创建的 Worktree，用户可修改参数后重试
```

---

### 3.2 审批流程

#### 触发
```
Agent 输出 [APPROVAL_REQUIRED]
  → 后端 approval-workflow 挂起 Agent 进程
  → 推送 approval:required 事件
    → TopNav 审批角标 +1
    → 右上角弹出通知卡片（非模态，不强打断）
       卡片显示：会话名 + 审批类型摘要
       用户可点击卡片 或 点击 TopNav 角标 进入 CommandCenter
```

#### 审批弹窗内容（按类型区分）

| 类型 | 展示内容 |
|------|---------|
| `destructive-op` | 危险命令高亮展示 + 警告说明（不显示 Diff） |
| `merge-ready` | 完整 Monaco Diff Viewer + 合并策略选择（squash / merge / rebase） |
| `checkpoint` | 不触发审批，见 3.5 |

所有类型均附带「回复 Agent」文本框，用户可在批准/拒绝时附带说明（如「请改用软删除」），消息注入 Agent 终端。

#### 批量审批
```
CommandCenter 审批队列支持：
  - 按类型过滤（merge-ready / destructive-op）
  - 勾选多条后批量「批准」或「拒绝」
  - merge-ready 类型可一键全部批准
  - destructive-op 类型默认需逐条确认
```

---

### 3.3 广播消息

```
CommandCenter → 广播面板
  → 展示所有活跃会话列表（多选框）
  → 用户手动勾选目标会话
  → 填写广播消息内容
  → 发送 → 消息注入所有勾选会话的 Agent 终端
```

---

### 3.4 Review & Merge 流程

```
Agent 完成任务 → 状态变为 completed
  → 画布节点 / 看板卡片颜色变更（不自动弹出任何打断）
  → 用户主动进入会话详情页
  → 点击「Review & Merge」按钮
  → 打开合并面板：
      - 完整 Monaco Diff Viewer（与 baseBranch 对比）
      - 合并策略选择：squash / merge / rebase
      - 确认合并 → 后端执行 mergeToBase → 状态变为 merged
      - 取消 → 保持 completed 状态，可稍后再合并
```

---

### 3.5 Checkpoint 进度汇报

```
Agent 输出 [CHECKPOINT] <描述>
  → 后端解析，推送 checkpoint:reached 事件
  → 前端更新：
      1. 画布节点 / 看板卡片上更新进度文字（最新 Checkpoint 描述）
      2. 会话详情页左侧「进度时间线」追加一条记录
         格式：时间戳 + Checkpoint 描述
  → 不触发任何通知或打断
```
---

### 3.6 画布节点交互

```
单击节点
  → 右侧滑出预览面板，展示：
      - 当前状态 + 最新 Checkpoint
      - 终端输出尾部（最近 10 行）
      - Diff 摘要（文件数 + 增删行数）
      - 快捷操作按钮（进入 Tab / 触发审批）
  → 预览面板不离开画布视图

双击节点
  → 跳转到该会话的详情 Tab
```

---

### 3.7 会话终止与清理

```
任何状态的会话均支持两步清理：

第一步：归档
  → 终止 Agent 进程（发 SIGTERM / kill PTY）
  → 保留 Git Worktree 和分支
  → 状态标记为 archived（可随时查看终端历史 / Diff）

第二步：彻底删除（在已归档会话上操作）
  → 弹出二次确认：「将删除 Worktree 目录和 agent/* 分支，不可恢复」
  → 确认 → 清理 Worktree 目录 + 删除本地分支 + 从 DB 移除记录
```

---

### 3.8 WebSocket 断线处理

```
连接断开
  → TopNav 连接状态指示灯变红
  → 鼠标悬浮指示灯显示：断开时长 + 已重试次数
  → 后台指数退避自动重连（不打断当前视图）

重连成功
  → 指示灯变绿
  → 拉取断线期间的终端 buffer 并回放到终端视图
  → 同步最新会话状态（防止断线期间状态变更丢失）

重连失败超过阈值（默认 10 次）
  → 指示灯变红并显示「×」标记
  → 顶部横幅提示「连接失败，请检查后端服务」+ 手动重连按钮
```
