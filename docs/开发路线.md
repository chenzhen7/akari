## 二、开发阶段规划

### Phase 1：后端核心骨架（预计 2-3 周）

目标：建立前后端分离的 monorepo 架构，实现后端核心服务与前端的基础通信。

| 优先级 | 任务 | 说明 |
|--------|------|------|
| P0 | Monorepo 迁移 | 将当前项目重构为 pnpm workspace 结构：`apps/web/` + `apps/server/` + `packages/shared-types/` |
| P0 | 后端脚手架 | Node.js + Fastify + TypeScript，配置热重载、ESLint、Prettier |
| P0 | WebSocket 通信层 | 建立前后端实时双向通道，定义消息协议（session 状态同步、终端输出推送） |
| P0 | SQLite 数据库 | better-sqlite3 集成，设计数据表：`sessions`、`approvals`、`terminal_logs` |
| P1 | Session Manager | REST API + WS：创建/查询/更新/删除会话，状态机管理 |
| P1 | 前端对接 | 将 Zustand store 从 mock 数据切换为真实 API 调用，保留 mock 模式作为开发开关 |

**Phase 1 完成标准**：
- 前后端可独立开发运行
- 前端能展示后端持久化的会话数据
- 会话的 CRUD 操作前后端同步

---

### Phase 2：Worktree + 终端复用（预计 2-3 周）

目标：实现 Agent 运行所需的物理隔离环境和终端 IO 捕获。

| 优先级 | 任务 | 说明 |
|--------|------|------|
| P0 | Worktree Manager | Git worktree 的创建/删除/清理，分支命名规范 `agent/<task>-<id>`，node_modules 符号链接复用 |
| P0 | 终端多路复用 | node-pty 集成：为每个会话创建独立 PTY，捕获 stdout/stderr，支持输入写入 |
| P0 | 终端 WebSocket 推送 | 终端输出实时推送到前端，支持滚动回溯、缓冲区管理 |
| P1 | 前端终端组件 | 基于 xterm.js 的终端渲染，支持 ANSI 颜色、滚动、清空 |
| P1 | 文件监听 | chokidar 监听 worktree 文件变化，实时计算 Diff |
| P2 | Diff Engine | 获取 worktree 与 base branch 的 diff，生成 stat/fullDiff/fileStatus |

**Phase 2 完成标准**：
- 前端点击"创建会话" → 后端真实创建 git worktree 和分支
- 终端输出可在前端实时查看
- 文件修改后 Diff 自动更新

---

### Phase 3：审批工作流 + Git 集成（预计 2 周）

目标：实现 Checkpoint 检测与审批流程，以及代码审查和合并能力。

| 优先级 | 任务 | 说明 |
|--------|------|------|
| P0 | Checkpoint 检测 | 终端输出解析 `[CHECKPOINT]`、`[APPROVAL_REQUIRED]` 标记 |
| P0 | 审批工作流 | 检测到审批点时暂停 Agent（停止输入），推送审批请求到前端 |
| P0 | 审批 UI 完善 | 前端展示审批原因、Diff 详情、批准/拒绝操作 |
| P1 | Git Diff 查看器 | Monaco Editor 集成，展示 side-by-side diff |
| P1 | 合并操作 | Squash/Merge/Rebase 策略，执行后清理 worktree |
| P2 | 批量审批 | 指挥中心面板支持批量批准/拒绝多个等待中的会话 |

**Phase 3 完成标准**：
- Agent 执行到审批点时自动暂停，前端收到通知
- 用户可在前端查看 Diff 并批准/拒绝
- 批准后 Agent 继续执行，拒绝后进入暂停状态
- 完成的会话可合并到主分支

---

### Phase 4：Agent 适配器（预计 2 周）

目标：接入真实的 AI Agent 工具，让平台真正运行 Agent。

| 优先级 | 任务 | 说明 |
|--------|------|------|
| P0 | Agent Adapter 接口 | 统一适配器协议：`start`/`pause`/`resume`/`sendMessage`/`onCheckpoint` |
| P0 | Claude Code Adapter | 调用 `claude` CLI，注入 checkpoint system prompt |
| P1 | Aider Adapter | 调用 `aider` CLI，配置 `--no-auto-commits` |
| P1 | 通用 Shell Adapter | 支持任意 shell 命令作为 Agent 入口 |
| P2 | Agent 配置管理 | 前端 UI 配置不同 Agent 的参数、环境变量 |

**Phase 4 完成标准**：
- 平台可启动真实的 Claude Code / Aider 进程
- Agent 在独立 worktree 中运行
- Checkpoint 标记被正确捕获并触发审批流

---

### Phase 5：视图联动与体验优化（预计 2 周）

目标：让多个视图无缝协作，提升使用体验。

| 优先级 | 任务 | 说明 |
|--------|------|------|
| P1 | 画布-看板-Tab 联动 | 状态变化时三个视图实时同步，看板拖拽自动更新画布位置 |
| P1 | 会话依赖连线 | 画布上支持连接会话节点表示依赖关系 |
| P1 | 全局搜索/过滤 | 按名称、标签、状态筛选会话 |
| P2 | 主题/暗色模式 | 完善暗色主题，终端配色适配 |
| P2 | 性能优化 | 大数量会话时的虚拟滚动、节点懒加载 |
| P3 | 导出/报告 | 会话执行报告导出（Markdown/PDF） |
